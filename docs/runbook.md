# PayPal Sandbox webhook runbook

## Register the listener

1. Deploy this revision and open the webhook URL below. A browser GET should return **405 Method Not Allowed**. A 404 means the live deployment lacks the route.
2. In the [PayPal Developer Dashboard](https://developer.paypal.com/dashboard/), open **Apps & Credentials**, select **Sandbox**, and choose the same Sandbox REST app Chaser uses for Invoicing.
3. In that app's **Webhooks** section, select **Add Webhook** and enter `https://paypal-ai-hackathon-9tkr.onrender.com/api/webhooks/paypal`.
4. Subscribe to the following [Invoicing events](https://developer.paypal.com/platforms/invoicing/reference/invoicing-webhooks/).
   - `INVOICING.INVOICE.PAID`
   - `INVOICING.INVOICE.CANCELLED`
   - `INVOICING.INVOICE.REFUNDED`
   - `INVOICING.INVOICE.CREATED`
   - `INVOICING.INVOICE.UPDATED`
   - `INVOICING.INVOICE.SCHEDULED`
5. Save the webhook and configure its ID as `PAYPAL_WEBHOOK_ID` on the Render service. Configure `PAYPAL_MODE=sandbox` and the existing Sandbox app and buyer settings using Render's environment controls. Keep credentials out of the repo and logs. The listener accepts `INVOICING.INVOICE.SENT` if offered or delivered by PayPal.

## Verify delivery and reconciliation

1. Issue an installment invoice from Chaser in Sandbox so its PayPal invoice ID is linked to a local invoice. Open its PayPal link and pay with the Sandbox buyer account.
2. In PayPal's [Webhook Events dashboard](https://developer.paypal.com/dashboard/webhooks), find the delivery for the Sandbox app. Confirm the paid event received HTTP 200. The [simulator](https://developer.paypal.com/api/rest/webhooks/rest/#test-the-listener-with-mock-events) does not support PayPal's postback signature verification. Use an event generated by the Sandbox app for end-to-end verification.
3. In Chaser, look for a `paypal` audit entry with action `webhook.processed` and the event ID. The invoice should show the authoritative paid amount, the installment count should update, and the last installment should resolve the plan and original chase state. The dashboard refreshes on SSE events. A duplicate event ID receives 200 without repeating the update.
4. For a 400 response, check that the transmission headers reached Render and the webhook ID belongs to this exact app/listener. For 503, check Sandbox credentials, webhook ID, and PayPal availability. A `webhook.invoice.unknown` audit entry means delivery succeeded but the event did not match a local invoice. A `webhook.processing.error` entry leaves work pending for the reconciliation fallback.

In mock mode, the workspace's **Simulate payment** button updates the mock provider and runs the same reconciler. For an isolated listener smoke test, POST an event with a fresh `id`, `event_type: "INVOICING.INVOICE.PAID"`, and `resource: {id: "<mock PayPal invoice ID>"}`, using `X-Chaser-Mock-Webhook: 1`. The event itself cannot change the mock provider's balance. The handler reads the provider record.

Render Free recreates its SQLite database after spin-down or redeploy. Use current demo invoices when testing and expect previously linked invoice IDs and webhook dedupe rows to be absent after a reset.
